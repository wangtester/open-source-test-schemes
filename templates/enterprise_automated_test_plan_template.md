### 2.1 测试套件规划与职责矩阵
| 测试套件层级 | 目标执行频率 | 运行耗时预算 | 依赖环境 | 覆盖率目标 | 核心职责 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **单元测试 (Unit)** | 提交前 / 本地热跑 | < 30 秒 | 纯内存，无外部 IO | ≥ 90% | 验证算法边界、工具函数、纯状态机流转 |
| **契约测试 (Contract)** | PR 门禁流水线 | < 2 分钟 | 轻量 Mock / 内存客户端 | 100% 接口覆盖 | 验证 Schema 兼容性、参数合法性与错误码矩阵 |
| **集成测试 (Integration)** | PR 门禁流水线 | < 5 分钟 | 瞬时隔离容器/真实临时进程 | 核心链路覆盖 | 验证多模块交互、数据库事务、消息流转 |
| **回放/快照测试 (Snapshot)** | PR 门禁流水线 | < 3 分钟 | 确定性引擎 / 虚拟时钟 | 核心事件覆盖 | 检验向后兼容性、事件序列不变性 |
| **端到端烟雾 (E2E Smoke)** | 发布前 / 夜间构建 | < 15 分钟 | 真实环境 / 发布产物 | 主干路径 100% | 验证真实安装包、网络连通性、用户主交互 |

## 4. 特殊测试模式与可靠性治理设计

### 4.1 物理副作用外部验证（Verify the World）
* **核心原则**：不信任系统的自述返回值。
* **落地方案**：
  * 文件操作：使用底层物理 API 直接校验磁盘文件哈希与权限。
  * 数据库操作：绕过业务缓存，直接开原生连接校验数据库落盘数据。
  * 进程调用：通过操作系统进程表验证 PID 生命周期与僵尸进程回收。

### 4.2 消除时间与环境非确定性（Deterministic Testing）
* **虚拟时钟（Virtual Clock / Time-Skipping）**：在涉及延迟任务与定时器时，挂载虚拟时钟推进，拒绝硬编码 `sleep()`。
* **动态资源隔离**：每个测试用例分配专有临时目录、随机端口、独立进程沙盒，杜绝状态交叉污染。

### 4.3 编译产物原生入口回归（Built-Artifact Smoke）
* 在流水线中引入对最终打包产物（`dist/bin`, `lib/index.js`, Docker 镜像）的直接执行校验，防止“开发态全绿，发布态崩溃”。

## 5. CI/CD 流水线与质量门禁设计

### 5.1 门禁指标配置
* **代码覆盖率**：要求单文件覆盖率（Per-File Coverage）达到既定阈值，禁止以大文件稀释边缘模块。
* **静态分析与代码健康度**：Linter（如 oxlint/eslint/golangci-lint）与类型检查（TypeScript/MyPy）零 Warning。
* **Flaky Test 零容忍策略**：建立测试失败诊断分类工作流，对偶现失败用例自动收集执行 Trace 与视频，限期治理。

### 5.2 并行化与性能预算
* **分片并发（Sharding）**：大型测试集拆分为 N 个并发分片并行运行。
* **超时熔断预算**：单个测试用例超时预算（如 5 秒），单套件超时预算（如 10 分钟），超时自动打出进程调用栈并强杀。
